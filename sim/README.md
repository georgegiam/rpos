# sim/

Phase 5 — the SimPy simulator that reproduces the protocol at large scale (N = 1k–10k), calibrated against and validated by the emulation testbed.

- `chord_sim.py` (#25) — converged Chord ring; analytic routing (`route()`, an exact port of `node/chord.py find_successor`) + a per-hop SimPy timing layer. Pure-Chord hops (matches theory ½·log₂N).
- `query_sim.py` (#26) — the DNS query path (Algorithm 2) on top of that ring: cache → DHT (primary + s replicas, majority vote) → fallback (iterative resolution + store-back), Zipf α=1.0 workload, cold-start warming. Emits per-query hops + latency. Run: `python -m sim.query_sim`. Delay weights are **calibrated against N=8/N=32 emulation (#29)** — `results/calibration.csv`.
- `calibrate.py` (#29) — calibrates the simulator against emulation. Runs `query_sim` at N=8 and N=32 with the frozen `PARAMETERS.md` parameters and compares p50/p95 latency, success rate and hop counts to the measured emulation (`results/experiments.csv` + `PARAMETERS.md` §2). Tuned the per-hop processing delay (1 → 18 ms), the fallback step (50 → 100 ms), and charges a routing hop as a full RTT (measured 5/50 ms netem legs stay frozen); all latency metrics land within ~8%. Writes `results/calibration.csv`. Run: `python -m sim.calibrate` (verify) or `--search` (re-derive the levers). Two flagged caveats: N=8 hop median is one below emulation (converged-ring idealisation, non-gating) and success-rate agreement is degenerate (no loss model).
- `ledger_sim.py` (#27) — the write path (Algorithm 3): chunk-ledger two-phase commit + TTL-expiry-driven re-resolution. Emits per-update latency, message count, and ledger growth. Run: `python -m sim.ledger_sim`.
- `churn_sim.py` (#28) — churn: nodes join/leave with exponential session times (birth–death, equilibrium ≈ N); every maintenance round (1.0 s) the successor absorbs a departed node's chunks. Sweeps mean session length → **raw DHT lookup success-rate curve** (data-availability model: a chunk is lost only if all s replicas depart within one repair window). Curve → `results/churn_sim_curve.csv`. Run: `python -m sim.churn_sim` (default N=100); `--n` takes a comma list, so the committed curve spans **N=100/1,000/10,000** (`python -m sim.churn_sim --n 100,1000`, plus an N=10,000 spot-check at sessions 10/60/3600 s) — the curve is ~N-invariant (per-chunk loss ≈ (repair/session)³, independent of ring size), which is the scalability evidence for A6. Stale-routing failures and numeric latency are out of scope (A6 / #29).
